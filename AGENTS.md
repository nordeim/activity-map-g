# AGENTS.md — ROAM (Augsburg City Guide)

Single Next.js 16 App Router app that clones `activity-map.base44.app`: a LOGIN-FREE city guide (fresh visitors are auto-signed-in as a seeded guest account; the demo login stays available at `/login`) with a trip-planner home page, Eat / Stay / Do browse views with measured filter chips, place detail with booking, a Leaflet map view, favourites, and a profile with trips + bookings. Prisma/SQLite persistence, cookie-session auth. Clone remote: `https://github.com/nordeim/activity-map.git`; pushes go to the SSH remote via `docs/ssh_git_wrapper_v3.py`.

**Gate order before every push:** `npm run lint` → `npm run typecheck` → `npm run test` (113) → `npm run build` → `./scripts/smoke-test.sh` (31, all must pass) → `npm run test:e2e` (93 Playwright checks — boots the production `next start` server on :3100 against its own `db/e2e.db`; RUN it, never trust `--list`). There is no hosted CI; the local gate is the only gate.

## Architecture facts you would otherwise guess wrong

- **Everything except `/login`, `/privacy-policy`, `/accessibility-statement`, and `/api` lives in the `src/app/(app)/` route group**, whose pages own the PATH-AWARE guest gate (`requireUser("/own-path")` from `src/lib/page-gate.ts`, v2.18): a session-less visitor is 307'd to the GUEST BOOTSTRAP (`GET /api/auth/guest?next=<page path>` — provisions/uses the seeded guest account, signs the session cookie, 303s back to the sanitised `?next=` as a RELATIVE Location — origin-agnostic behind any reverse proxy, v2.17; and DEEP LINKS SURVIVE the login-free first visit, v2.18: the layouts CANNOT know the request path — verified: `headers()` exposes only proxy headers — so the gate lives in each page, where the path is known; pinned by `tests/e2e/guest.spec.ts`'s deep-link pins for /eat, /map, /place/*, /profile). The `(app)`/`(bare)` layouts are CHROME-ONLY: they resolve the session for the Navbar (rendering it only when a user exists — the parallel-render window before the page's 307 aborts the response) and no longer redirect. Every page in the groups MUST call `requireUser` — an ungated page fails loudly (its user-dependent data path surfaces the missing session), never silently. `/login` is a real route (server component) that renders the login form for EVERYONE (v2.21 — the live's /login does NOT redirect authenticated visitors; the old bounce-to-/ was clone invention) and remains the only place the demo-account login form appears; the two legal pages are public static routes (session-25: the live's routes `/privacy-policy` + `/accessibility-statement`; the legacy `/privacy` + `/accessibility` paths remain as permanent redirect stubs). **EXCEPTION (session-16): `/profile` lives in the `src/app/(bare)/` route group** — same page-level guest gate, but NO Navbar and NO SiteFooter (the live's profile is a chrome-less page). **Session-30: the two 404 designs** — an invalid place slug renders `src/app/(app)/place/[slug]/not-found.tsx` (an IN-APP page inside the (app) chrome: the 46px serif ink "Place not found" h1 + the 44px ink "Back to Do" pill → /do on a `min-h-screen bg-cream px-5 py-24 text-center` block), while an unknown route renders the root `src/app/not-found.tsx` as the platform's chrome-less SLATE design (the 72px font-light slate-300 "404" + the 64×2 divider + "Page Not Found" 24px + the quoted path via `useSyncExternalStore` + the white bordered r-8 "Go Home" link → /) — never render the old custom cream "Off the map" page again. **Session-31: the generic 404's quoted path reads `window.location` through `useSyncExternalStore`** (getServerSnapshot returns `""`) — the page is statically prerendered, so `usePathname()` bakes `"_not-found"` into the server HTML and mismatches at hydration (a React #418 console error on EVERY visit, caught on the deployed mirror); the store pattern swaps the real path in AFTER mount with no mismatch (`tests/e2e/not-found.spec.ts` pins zero console errors).
- **The API envelope is `{ ok: true, data } | { ok: false, error: "<message>" }`** with real HTTP status codes (401/400/404/429/201). Follow the existing route handlers' shape; do not introduce a nested error object.
- **Auth is hand-rolled** (`src/lib/auth.ts`): scrypt password hashes + HMAC-SHA256-signed stateless cookie `roam_session` (7-day TTL, httpOnly/lax, secure in production, keyed by `AUTH_SECRET`). `getSessionUser()` guards every route handler and the app layout. No NextAuth, no JWTs, no middleware. **Guest-first (login-free first visit)**: the `(app)`/`(bare)` layouts redirect session-less visitors to `GET /api/auth/guest` (`src/app/api/auth/guest/route.ts` + `src/lib/guest.ts`, pinned by `tests/guest.test.ts`), which provisions/uses the ONE shared guest account (`guest@roam.local`, name "Explorer" — the live's anonymous default identity, seeded by `prisma/seed.ts`, password a discarded random 32-byte secret so the account can NEVER be signed into via /api/auth/login), signs the ordinary `roam_session` cookie, and 303s back to the SANITISED `?next=` (`sanitizeNextPath`: local absolute paths only — absolute/protocol-relative/backslash URLs, relative paths, control chars, and the bootstrap path itself all fall back to `/`; the Location is a RELATIVE reference, so it can never encode a host — v2.17, the live reverse-proxy localhost-bounce regression; an existing valid session is never clobbered; NOT rate-limited — no credentials to brute-force). Signing out now returns to `/` and re-bootstraps a fresh guest session instead of surfacing the login wall. Login is rate-limited (`src/lib/rate-limit.ts`): 10 attempts/IP/15 min sliding window → `429` with `Retry-After`; in-memory, single-node only. ## Conventions that differ from defaults

- Prices format via `src/lib/utils.ts` (`formatPrice` en-IE EUR, `priceRangeSymbols` 1–4 → €..€€€€ + `priceRangeParts` for the ACTIVE+DIMMED card display, `formatDuration` minutes → "2 h"); planner URL/date-label helpers live in `src/lib/planner.ts`. Don't hand-roll display formatting in components.
- Place rows store JSON arrays in plain string columns (`vibeTags`, `galleryImages`, …) — SQLite has no array type; `toPlaceDTO` in `src/lib/places.ts` is the only sanctioned parser, and every API payload uses the `PlaceDTO` shape from `src/types/index.ts` (including the per-user `saved` flag).
- Bookings persist the session-3 request-form fields (`name`, `surname`, `time`, `phone`, `email`, `message` on the `Booking` model); guests clamp to the place's `minParty`/`maxParty` server-side; the profile view groups bookings with place names client-side and splits Upcoming/Past through `isBookingPast` (`src/lib/bookings.ts`) — CALENDAR-DAY comparison, so a same-day reservation stays Upcoming (the smoke + E2E booking fixtures use runtime-computed dates, never hardcoded ones that rot).
- E2E auth is shared: the Playwright `setup` project signs in ONCE into `tests/e2e/.auth/user.json` (storageState) because per-test logins would trip the rate limiter. `auth.spec.ts` (the login surface) and `guest.spec.ts` (the login-free first visit) opt out with an empty storageState to test the logged-out / guest surfaces. Spec navigations use `waitUntil: "domcontentloaded"` — the home page pulls ~35 card images from the reference CDN and the full `load` event has hit spurious 45s timeouts under network contention. Never leave a stray server on :3100 — `reuseExistingServer` reuses a STALE build mid-iteration (session 6: a stale probe server produced a phantom favourites failure); also close stray headless-browser sessions + the dev server before a suite run — a full E2E pass with several browser daemons alive exhausted the 4GB sandbox and crashed the browser targets (session-14 lesson). The auth spec's /login gotos use `domcontentloaded` too (session-14: the CDN-font `load` flake).
